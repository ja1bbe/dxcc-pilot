自局の設定とログの確認

自局のコールサインとメールアドレスを設定ファイルに書き、スクリプトが HAMLOG の交信記録を正しく読めるかを確かめます。

settings.ini を書く

C:\dxcc-pilot\settings.ini を右クリックし、「プログラムから開く」→「メモ帳」で開きます。「＜＞」の部分を、ご自分の値に書き換えます。

[station]
my_call = JA1ABC
mail_from = ja1abc.dxcc@gmail.com
mail_to = 受信用のアドレス
my_grid = PM85
lotw_user =
lotw_cert_start =

[sites]
home = 自宅
項目書く内容
my_call自局のコールサイン。交信済みの判定には、ここに書いたコールでの交信だけを数えます。
mail_from通知を送るGmailのアドレス（画面4で作るもの）。先に決めておいて構いません。
mail_to通知を受け取るアドレス。送信用とは別のアドレスにします。
my_grid自局のグリッドロケータ（4桁か6桁）。書くと、通知にアンテナを向ける目安の方位が付きます。空けておいても動きます。
lotw_userLoTW を使う方だけ（画面6で説明します）。今は空けておきます。
[sites]このPCの名前。通知メールの件名に入ります。1台だけなら、このままで構いません。

保存するときは「名前を付けて保存」で、下の「エンコード」が UTF-8 になっていることを確かめます（Windows 11 のメモ帳は、通常 UTF-8 で保存されます）。パスワードはこのファイルには書きません。

複数のコールサインの交信を合算するとき

以前のコールサインや移動運用のコールでの交信も合算する場合は、my_call = JA1ABC, JA1ABC/1 のようにカンマで区切って並べます。ARRL の DXCC では、本人が免許を受けたコールで、同じエンティティ（日本）から運用した交信を合算できます。他局の設備でその局のコールを使った運用（ゲスト運用）は、本人の実績になりません。ご自身の状況は、ARRL の最新の DXCC ルールで確かめてください。

HAMLOG の備考に %GestOP: の記録がある交信や、送信したコールサイン（$C=）が自局と違う交信は、ゲスト運用として交信済みに数えません。

HAMLOG の交信記録が読めるか確かめる

コマンドプロンプトで、次の2行を順に実行します。2行目の HAMLOG のデータファイルの場所は、ご自分の環境に合わせて書き換えてください。

cd /d C:\dxcc-pilot
python hamlog_reader.py "C:\Hamlog\HAMLOG.hdb"

次のように、件数と期間が表示されます（数字は例です）。交信の中身は表示しません。

自局のコールサイン: JA1ABC
読み込んだ交信: 10215件（自局 10170件、ゲスト運用など 45件）
期間(UTC): 2003-09-06 〜 2026-12-20
記録の時刻: {'JST': 6120, 'UTC': 4095}
...
点検: {'date_unknown': 3, 'deleted': 12, 'bad_band': 5}
  • 読み込んだ交信の件数が、HAMLOG に記録されている交信の数とほぼ合うことを確かめます（HAMLOG で削除した記録は数えません）。
  • 期間が、最初の交信から最近の交信までになっていることを確かめます。
  • bad_band は、周波数の欄からバンドを判定できなかった件数です。入力の誤りがあると数が増えます。数件なら、そのまま進めて構いません。

件数が大きく違うとき

HAMLOG のデータファイルの読み方は、公式の仕様ではなく、筆者の局のデータで確かめたものです。件数や期間が大きく違う場合は、この先へ進まず、表示された内容を添えてお問い合わせください（画面6）。

ADIF形式のログを使う場合

HAMLOG を使っていない場合や、ほかのソフトの交信も合わせたい場合は、ADIF形式のファイル（拡張子 .adi）を C:\dxcc-pilot\logs に置きます。HAMLOG と両方ある場合は、同じ交信を1件として合わせて判定します。

ここまでの確認

  • settings.ini に自局のコールサインと2つのメールアドレスを書き、UTF-8 で保存した。
  • hamlog_reader.py の件数と期間が、HAMLOG の記録とほぼ合っている。
