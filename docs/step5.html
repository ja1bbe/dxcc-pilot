WSJT-X・JTAlertとつないで起動する

WSJT-X のデコード結果を、JTAlert と通知スクリプトの両方が受け取れるようにし、起動用のファイルを作って、本番どおりに動かします。

WSJT-X の送り先をマルチキャストにする

WSJT-X の初期設定（127.0.0.1）では、デコード結果を1つのソフトにしか渡せません。複数のソフトが同時に受け取れる「マルチキャスト」に変えます。WSJT-X の「設定」→「Reporting」タブで、次のように設定します。

項目設定値
UDPサーバー239.255.0.1
UDPサーバーのポート番号2237（変更なし）
データ送出インターフェイスloopback_0
マルチキャストTTL1

JTAlert は起動時に WSJT-X の設定を読み込むので、JTAlert 側でアドレスを設定する必要はありません。同じ PC で2つ目の WSJT-X を動かす場合は、そちらを 239.255.0.2・2238 のように分けます。

設定を変えたあとは、JTAlert を完全に終了する

JTAlert を閉じても、画面右下のタスクトレイに残っていることがあります。そのまま起動し直すと「2nd Instance」になり、WSJT-X の起動を待ったまま止まってしまいます。タスクトレイも含めてすべて終了してから、起動し直してください。

JTAlert の判定をバンドごとにする

JTAlert の「Settings」→「Wanted DXCC」の「Tracking」を「By Individual Band」（バンドごと）にします。通知スクリプトと同じ考え方にそろえておくと、JTAlert の画面の色分けと通知の判断が食い違いません。

起動用のファイルを書き換える

C:\dxcc-pilot\start_dxcc.bat を右クリックし、「編集」（または「プログラムから開く」→「メモ帳」）で開きます。書き換えるのは次の行だけです。

set HAMLOG=C:\Hamlog\HAMLOG.hdb

画面3で確かめた HAMLOG のデータファイルの場所に書き換えて、上書き保存します。WSJT-X の設定を上の表と違う値にした場合は、--group と --port も同じ値にします。

デスクトップから起動できるよう、start_dxcc.bat を右クリックし、「その他のオプションを確認」→「送る」→「デスクトップ (ショートカットを作成)」を選びます。

起動の順番

起動は、必ず次の順番にします。受信機を後から起動すると、WSJT-X に受信音が届かないことがあります。

SDRconnect または無線機 → WSJT-X → JTAlert → start_dxcc.bat

受信できているか確かめる

初めての起動では、デコードを受け取れているかを画面で確かめます。コマンドプロンプトで次のように実行します（HAMLOG の場所は書き換えてください）。

cd /d C:\dxcc-pilot
python dxcc_notify.py --site home --debug-udp --hamlog "C:\Hamlog\HAMLOG.hdb"

起動すると、次のように表示されます（数字は例です）。

dxcc-pilot 版 1.0.0
自局のコールサイン: JA1ABC
listening 239.255.0.1:2237  bands=['10m', '12m', ...]
log total: 1520 entity-band pairs
開始のメールを送りました

WSJT-X がデコードするたびに、その行が画面に流れれば、すべての経路がつながっています。同時に、スマートフォンには開始（START）のメールが届きます。確かめられたら Ctrl＋C で止めます。止めると、終了（STOP）のメールが届きます。

以後は、--debug-udp を付けずに、デスクトップのショートカットから起動します。

「0.0.0.0 で参加できませんでした」と表示されたとき

スクリプトは2つの受信経路を用意しており、使わない方の案内です。もう一方の経路（ループバック）で受信できていれば、問題ありません。

初めての起動で Windows のファイアウォールの確認画面が出た場合は、「プライベートネットワーク」での通信を許可してください。

ここまでの確認

  • 起動画面に「listening」と表示され、デコードの行が流れる。
  • 開始（START）のメールと、Ctrl＋C で止めたときの終了（STOP）のメールが届いた。
