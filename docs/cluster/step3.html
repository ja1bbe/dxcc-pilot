試してから起動する

まずメールを送らずに動きを確かめ、次にテストメールを送ってから、本番どおりに起動します。DXCC代行ワッチと同時に動かす方法も説明します。

メールを送らずに試す

コマンドプロンプトで、次のように実行します（HAMLOG の場所は、ご自分の環境に書き換えてください）。

cd /d C:\dxcc-pilot
python cluster_watch.py --dry-run --hamlog "C:\Hamlog\HAMLOG.hdb"

起動すると、次のように表示されます（数字は例です）。

cluster_watch 版 0.1.0（dxcc-pilot の追加機能）
自局: JA1ABC / モード: FT8, CW, SSB / バンド: 160m, 80m, ... / 通知: 全バンド初のみ / 取得先: dxscape, dxsummit
交信済み: 1520 組（エンティティ×バンド）、エンティティ 248
[DRY] [クラスター] 🔴全バンド初 30m FT8 TN8GD (Republic of the Congo)

2行目に、settings.ini で書いた条件がそのまま表示されているか確かめてください。3行目のエンティティの数は、DXCC代行ワッチの開始のメールに出る全バンドの交信数と、ほぼ同じになるはずです。未交信の局がスポットされていれば、「[DRY]」の行で、送るはずだったメールの件名が表示されます。スポットがないときは何も表示されないので、しばらく待ってください。確かめられたら Ctrl＋C で止めます。

「HAMLOG を読めないため、30秒後に読み直します」と表示されたとき

HAMLOG が交信の記録中だったり、ほかのソフトが読んでいたりすると、一時的に読めないことがあります。スクリプトは自動で読み直します。読めないまま交信済みを数えると、ゲスト運用の交信が紛れ込むため、読めるまで待つようにしてあります。何度も続く場合は、--hamlog の場所が正しいかを確かめてください。

テストメールを送る

python cluster_watch.py --test

スマートフォンに「[クラスター] テスト通知」が届けば、メールの経路は大丈夫です。

起動用のファイルを使う

C:\dxcc-pilot\start_cluster.bat をメモ帳で開き、HAMLOG の場所の行を、start_dxcc.bat と同じに書き換えます。

set HAMLOG=C:\Hamlog\HAMLOG.hdb

デスクトップにショートカットを作っておけば、ダブルクリックで起動できます。止めるときは、そのウィンドウで Ctrl＋C を押すか、ウィンドウを閉じます。

DXCC代行ワッチと一緒に動かす

両方を同時に動かすときは、start_dxcc.bat の python dxcc_notify.py の行の前に、次の1行を加えます。

start "DXCLUSTER" /min python cluster_watch.py --site home --stop-with-wsjtx %HLOPT%

python dxcc_notify.py の行は、止めるまで次の行に進みません。後ろに書くと、DXクラスター通知が始まらないため、必ず前に書きます。start を付けると、最小化した別のウィンドウで動きます。

--stop-with-wsjtx を付けると、WSJT-X を閉じたとき、2〜4分でDXクラスター通知も自動で終わります。代行ワッチのウィンドウで Ctrl＋C を押しても、DXクラスター通知は止まらないので、WSJT-X を開いたまま止めたいときは、タスクバーの「DXCLUSTER」のウィンドウを閉じてください。

同じ局を両方が知らせることがあります

受信中のバンドで未交信の局がスポットされると、代行ワッチ（件名「[DXCC]」）とDXクラスター通知（件名「[クラスター]」）の両方からメールが届くことがあります。件名の先頭で見分けられます。

ここまでの確認

  • --dry-run で、設定した条件と交信済みの数が正しく表示された。
  • テストメールがスマートフォンに届いた。
  • 起動用のファイル（または start_dxcc.bat の1行）で起動できた。
