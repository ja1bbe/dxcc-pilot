全体像と準備するもの

日本の局が DX クラスターに上げたスポットを見張り、自局が未交信のエンティティが見つかったときだけ、スマートフォンにメールで知らせる仕組みです。FT8・CW・SSB などのモードと、全バンドか特定のバンドかを選べます。DXCC代行ワッチ（dxcc-pilot）の追加機能として、同じフォルダに入れて使います。

どのように動くのか

スクリプト cluster_watch.py が、2分ごとに次の2か所からスポットを取得します。

  • DXSCAPE の JA25：日本からのスポットの直近25件を表示しているページです。
  • DX Summit：世界中のスポットが流れるサイトです。このうち、スポッターのコールサインが日本の局のものだけを使います。

スポットのモード・バンドが、設定で選んだものに当てはまり、そのエンティティが未交信であれば、メールを送ります。交信済みかどうかは、DXCC代行ワッチと同じく、HAMLOG の自局の交信と logs フォルダの ADIF で判定します。ゲスト運用（他局のコールサインでの運用）の交信は数えません。

DXCC代行ワッチとの違い

DXCC代行ワッチDXクラスター通知
手がかり自局の SDR・無線機で受信した FT8日本の局が上げたスポット
モードFT8FT8・FT4・CW・SSB から選ぶ
バンド受信中のバンドだけ全バンド、または選んだバンド
無線機・WSJT-X必要不要（PC とインターネットだけで動く）
確かさ自局で実際に聞こえた局日本のどこかで聞こえた局（誤ったスポットもある）

代行ワッチで 7MHz を受信している間に、14MHz に未交信の局が現れても気付けません。DXクラスター通知は、その欠点を補います。両方を同時に動かすこともできます（画面3）。

準備するもの

DXCC代行ワッチの構築手順のうち、次の画面を済ませていることが前提です。Python、国別データ、自局の設定、Gmail の準備は共通なので、もう一度行う必要はありません。

  • 画面2：Pythonとファイルの準備（Big CTY の cty_latest.dat と cty_latest.csv を含む）
  • 画面3：自局の設定とログの確認（settings.ini の [station]）
  • 画面4：Gmailの準備（環境変数 DXCC_MAIL_PASS の登録とテストメール）

代行ワッチ（WSJT-X との接続）を使わず、DXクラスター通知だけを使う場合も、この3つの画面は必要です。

ファイルを入手する

これから DXCC代行ワッチの画面2で初めてスクリプト一式を入手する方は、その中に DXクラスター通知のファイルもすでに含まれているので、この節の作業は不要です。次の「スポットの提供元への配慮」に進んでください。

すでに DXCC代行ワッチを使っている方は、次の手順で、DXクラスター通知に必要なファイルを加えます。

  1. スクリプト一式（ZIPファイル）をダウンロードします。
  2. ダウンロードした dxcc-pilot-main.zip を右クリックし、「すべて展開」を選びます。
  3. 展開してできた dxcc-pilot-main フォルダを開き、次の4つのファイルを選んでコピーし、C:\dxcc-pilot に貼り付けます。「同じ名前のファイルがあります」と表示されたら、「ファイルを置き換える」を選びます。
cluster_watch.py      … DXクラスター通知の本体（新規）
start_cluster.bat     … 起動用ファイルの見本（新規）
hamlog_reader.py      … 2つのスクリプトが同時に HAMLOG を読めるよう修正
dxcc_notify.py        … HAMLOG を読めなかったときの扱いを修正
  1. dxcc-pilot-main フォルダの settings.ini をメモ帳で開き、[cluster] の行から最後までを選んでコピーします。
  2. お手元の C:\dxcc-pilot\settings.ini をメモ帳で開き、一番最後に貼り付けて、文字コードを「UTF-8」にして保存します。

settings.ini はファイルごと置き換えない

settings.ini には、画面3で書き込んだ自局のコールサインやメールアドレスが入っています。ファイルごと置き換えると、それが見本の値に戻ってしまいます。必ず [cluster] 以下の部分だけを貼り付けてください。common フォルダや logs フォルダも、コピーしないでください。

hamlog_reader.py と dxcc_notify.py も入れ替える理由

古い版のまま2つのスクリプトを同時に動かすと、HAMLOG の読み込みがぶつかって失敗することがあります。失敗すると、ADIF のうちゲスト運用の交信を見分けられず、交信済みが多めに数えられて、未交信の通知が漏れます。新しい版ではこれが起きないようにしてあります。

スポットの提供元への配慮

DXSCAPE と DX Summit は、どちらも個人や団体が運営しているサイトです。このスクリプトは、取得の間隔を60秒より短くできないようにしてあります。間隔を短くしすぎないこと、取得したデータを再配布しないことをお守りください。

ここまでの確認

  • DXCC代行ワッチの画面2〜4を済ませ、テストメールが届いている。
  • C:\dxcc-pilot に cluster_watch.py があり、settings.ini の末尾に [cluster] の欄がある。
